# Инцидент 2026-08-25: после «Забрать бесплатный месяц» ссылка не пришла

## TLDR

Новый юзер (user 1000054, подписка 11055) тапнул в боте «🎁 Забрать бесплатный
месяц», получил «🎉 Готово! … Сейчас пришлю ссылку для подключения» и больше
ничего. Повторный тап дал «Подарок уже был использован … Тарифы:» и платный прайс
без пути к ссылке. Причина: `cmd_config` в `bot/handlers.py` после фикса
паритета (5d696f6, 2026-08-21) содержал вложенный `_say`, который при живом
`message` вызывал **сам себя** вместо `message.answer` → `RecursionError`
сразу после «Готово!». Тот же `cmd_config` обслуживает `/config` и кнопку
«Мой конфиг», поэтому с 21.08 команда была сломана для всех, не только для
триальщиков (в прод-логе за 120 ч ровно один RecursionError: этот юзер;
`/config` за это время никто не звал).

Второе дно: канал пуша «✅ Конфиг VPN готов! Ссылка: …» (`config_ready`)
бот умел доставлять, а бэкенд его **никогда не писал**: `_notify_bot_config_ready`
клал `_notify` в `ProvisioningTask.result`, который никто не читал. Отложенной
доставки не существовало, и после оплаты картой (lava-вебхук) юзер тоже не
получал от бота ничего, хотя при выставлении счёта бот обещал «Конфиг придёт
автоматически».

## Как нашли

1. Скриншот переписки: «Готово! … Сейчас пришлю ссылку» в 23:49 по часам
   юзера, дальше тишина; повторный тап → «уже использован» + прайс.
2. Прод-лог бота (`ansible nl-web -m shell -a "cd /opt/vpn && docker compose logs
   --since 120h bot | grep -B45 RecursionError"`): трейс
   `trial_activate_cb → cmd_config → _say → _say …` («Previous line repeated 964
   more times»), 18:49:23Z = 21:49 МСК, совпадает со скриншотом.
3. Юзер: `GET /api/audit-logs?action=trial_activated_full&limit=5` через
   admin-API → `user:1000054`, subscription 11055; `GET /api/users/1000054` →
   Solo, active, ufo-ru-01, четыре живых креда. Ссылка исправна, её просто не
   отдали.
4. `git blame` строки `await _say(text, **kwargs)` → 5d696f6.

## Что сделано

### Бот

- `cmd_config._say` → `message.answer` (эталон был рядом: `list_plans._say`).
  `cmd_config` возвращает `bool` и умеет `quiet_if_missing` (молчит про «нет
  подписок / /plans», но честные статусы «⏳ ещё создаётся» и «❄️ заморожена»
  шлёт всегда).
- `trial_activate_cb`: доставка ссылки обёрнута в `_try_send_sub_link` — любое
  исключение логируется и заменяется фолбэком «забери в личном кабинете
  (кнопка внизу) или /config». Обещание ссылки больше не может оборваться молча.
  Ветка 409 ветвится по `detail`: живая подписка → ссылка без прайса;
  `RuntimeError` провижининга (бонус зачислен, подписки нет) → честный текст и
  `/help`; иначе прежнее поведение.
- «Посмотреть потом»: новый callback `go:config` и кнопка «🔗 Ссылка для
  подключения» на главном экране и перед прайсом «💎 Подписка» у всех, у кого
  есть подписка (`has_subscription` из `/api/users/register`, а не только
  active-девайсы).
- Акцент на ЛК: кнопка «🔐 Открыть личный кабинет» первой строкой в
  `onboarding_keyboard` (идёт с ссылкой в `/config`, после Stars-оплаты и в
  пуше `config_ready`); строка «ссылка всегда лежит в личном кабинете (кнопка
  «Личный кабинет» внизу) и по команде /config» в шапке ссылки и в тексте
  после активации; все упоминания «/config» в подсказках дополнены ЛК.
- Структурный тест: ни одна вложенная функция в `bot/handlers.py` не вызывает
  саму себя по имени (`backend/tests/test_bot_sublink_delivery.py`), плюс
  поведенческие тесты всех веток. Общий стаб aiogram для bot-тестов вынесен в
  `backend/tests/_bot_stubs.py` (старый стаб отстал от импортов и держал CI
  красным).

### Бэкенд: живой `config_ready`

`backend/app/services/config_ready.py::notify_config_ready` пишет
`AuditLog(action="config_ready")` с `sub_uri`, поллер бота доставляет как
раньше. Гейт от спама структурный: флаг `notify_config_ready` в payload ставит
**только** cold-ветка `provision_subscription`; warm-хит там же зовёт хелпер
напрямую. Failover/миграции/свопы/разморозка/добавление устройства идут через
`reprovision_subscription` и пуш дать не могут. Внутри хелпера: telegram_id из
цифр, подписка `active`, девайс active с живым кредом, это первый рабочий
девайс подписки (revoked-строки не удаляются и блокируют повтор), подписке
меньше 24 ч, нет строки `config_ready`/`config_ready:delivered` по подписке.
Запись под SAVEPOINT: сбой пуша не роняет провижн и не отравляет сессию.
На warm-хите из бота юзер получает ссылку дважды (inline + пуш через ≤10 с как
«готово, можно подключаться») — осознанная страховка. Подробнее:
`docs/components/provisioning.md`.

## Ремедиация юзера 1000054

Ссылка: `https://grwr.ink/<sub_token>` (раскладка 50/50 по sha256 токена, как у
бота; проверено `HTTP 200`, 9 КБ конфигов). Дослать адресной рассылкой:

```bash
TOK=$(ansible-vault view --vault-password-file ~/.vpn_vault_pass \
  infra/ansible/group_vars/web/vault.yml | grep vault_admin_api_token | sed 's/.*: *//; s/"//g')
curl -sS -X POST -H "X-Admin-Token: $TOK" -H "Content-Type: application/json" \
  -d '{"text":"<текст со ссылкой и подсказкой про личный кабинет>","target_filter":{"type":"ids","ids":[1000054]}}' \
  https://grinwer.online/api/broadcasts
```

После деплоя юзеру также хватит `/config` или кнопки «Личный кабинет».

## Уроки

- Вложенный хелпер с тем же именем в двух функциях: копипаста
  `list_plans._say` → `cmd_config._say` с опечаткой в одной строке. Теперь
  ловится AST-тестом.
- Обещание в тексте («сейчас пришлю») должно быть подкреплено фолбэком на
  исключение, а не только на «нет данных».
- Канал уведомлений с читателем без писателя жил четыре месяца, потому что
  документация описывала его как рабочий. Проверять писателя grep'ом по
  литералу `action="…"`, а не по докам.
