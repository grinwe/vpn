# Чек-лист приёмки ноды и exit-а

**Зачем.** 29.09.2026 разбирали жалобы «на одном из протоколов Gemini и сайты видят Россию». Утечки не нашлось: Google геолоцирует как RU exit-ы `dc-cz-01` (103.119.18.55), `dc-nl-01` (45.81.35.97) и direct-ноду `4vds-dk-01`. Юзер с легом через такой выход получал «сервис недоступен в вашей стране», после смены протокола попадал на лег с другим exit-ом, и всё «чинилось». Пайплайн этого не ловит: после успешного bootstrap нода сразу уходит юзерам. Раньше по жалобам находили и другое: hy2 на relay выпускал трафик с RU-IP (до 28.07), истекли xhttp-серты (22.07), не было DNAT для хоппинга hy2 (25.08), NAT на exit-е не переживал ребут, в раскладке 4×1 появлялись дыры.

**Когда применять:** новая VPN-нода (RU relay или зарубежная direct), новый WG exit, смена IP или хостера. Раздел 7 проходить регулярно.

**Обозначения.** (RU) только RU relay-нода, (зарубеж) только зарубежная direct-нода, (exit) только WG exit; без метки для любой ноды. «Оператор» / «запускает оператор»: агентской сессии это режет классификатор (запись в прод-API, ansible/ssh на ноды, скачанные бинари), запуск через `!`, вывод в файл, `< /dev/null`. Вывод ansible-команд и выгрузки пробника (в них креды) класть ВНЕ репо, в `~/.cache/vpn-egress-probe/out/` (`O`): деплой rsync-ает рабочее дерево целиком и `.gitignore` не читает, так что файлы из `infra/ansible` или `scripts/egress_probe` уехали бы в `/opt/vpn` на прод. Скрипты пробника: `P=<корень репо>/scripts/egress_probe`. Админ-API: `scripts/egress_probe/admin_api.py METHOD /api/... [JSON]`. «На ноде»: по SSH провижининг-ключом (путь см. первый пункт раздела 2), многострочное через `ansible ... -m script`. «SQL»: на nl-web `cd /opt/vpn && docker compose exec db psql -U vpn -d vpn -c "<запрос>"` (оператор). Источники: `.md` без пути лежат в `docs/operations/`; «аудит 28.07» = ru_split_routing_audit_2026_07_28.md, «fleet-ранбук» = fleet_unification_xray_ws_runbook_2026_07_23.md, «reality-ранбук» = reality_nd_analysis_and_runbook_2026_07_23.md; `.py` без пути в `backend/app/`, roles/ и playbooks/ в `infra/ansible/`; memory: <имя> = `~/.claude/projects/-home-ataradin-work-ai-vpn/memory/<имя>.md`.

## Главное

- **Стейджинга в коде нет.** По умолчанию `is_active=true`, успешный bootstrap сам переводит ноду registering→active без проверки качества, а `choose_node` берёт наименее загруженную: новая нода идёт первой под покупки, диверс-добор и failover. Держать `is_active=false` до конца серверных проверок.
- **Выключенную ноду клиентом не проверить**: `migrate_device_to_node` требует `is_active`, warm-пул выключенные не греет. Окно «включена, но не принята» держать коротким, в тихие часы, проверять тест-устройством sub 21.
- **Attach exit-а сразу даёт ему боевой трафик**: `choose_exit_for_relay` не смотрит `is_active`, `status` и handshake. Exit проверяется до attach к relay с юзерами.
- **Раскатка только через API.** `site.yml` по статике без тегов (или `-l <нода>`) на хостах vpn_nodes гоняет `relay_jump_node` без `relay_wg_*`, а это teardown WG-туннелей и откат split: трафик пойдёт с RU-IP. По статике `site.yml` только с `--tags monitoring|backup|app|web`. P1/P2 в `relay-migration.md` устарели. _(infra/ansible/site.yml)_
- **Не деплоить `--tags app`/`web`, пока идут таски приёмки** (`GET /api/provisioning/tasks?status=running` и `?status=pending`): рестарт их прерывает, а старт backend (`reset_stuck_tasks()`) переставляет все running флота в очередь; таска без RQ-джобы висит pending и держит `uq_active_node_bootstrap`, снимать `POST /api/provisioning/tasks/{id}/cancel`. _(backend/app/main.py; memory: project_hy2_batch_resync, feedback_deploy_via_ansible)_
- **Кнопки с побочным эффектом** (детали ниже): `POST /api/provisioning/queue/reset-stuck` (переставляет все running и pending флота), `POST /api/diagnostics/node/{id}/disable` и `POST /api/nodes/{id}/auto-diagnose/disable` (нода пропадает из саб-ссылок и `choose_node`), смена reality-SNI (рвёт клиентов ноды до перечитки сабы), `POST /api/subscriptions/bulk-rebuild-config` (URI юзера на всех нодах его набора).

Юзеры: SQL `SELECT DISTINCT d.user_id FROM credentials c JOIN devices d ON d.id=c.device_id WHERE c.node_id=<id> AND c.is_active;` → старые бандлы не раздаются, sni ws-cdn/xhttp не меняется за жизнь ноды. _Почему: warm-бандл запекает config_text; пересоздание конфига минтит новый поддомен и удаляет CF-запись (configs 20/29: 51 и 31 сирота); rebuild по недоделанной ноде раздаст несуществующий URI (api/subscriptions.py `bulk_rebuild_config`; fleet-ранбук, шаг R; memory: project_reconciler_cdn_inflight)._
- [ ] **Новый протокол на живой ноде дошёл до всех держателей, включая diverse** — `POST /api/nodes/{id}/configs`, `POST /api/nodes/{id}/backfill-missing-creds`, resync success, `POST /api/subscriptions/bulk-rebuild-config` (SQL выше) → у home и diverse есть кред, /sub его отдаёт. _Почему: бэкфилл фильтровал по домашней ноде, diverse не получали ws-cdn и hy2 (memory: project_443_unification; docs/NODES.md)._

## Инструменты

`scripts/egress_probe/` (`P`): скрипты. Данные (`nodes.json`, `user1.json`, `creds*.json`, `probe*.jsonl`, `*.out`) держать в `~/.cache/vpn-egress-probe/out` (`O`): в них креды, а деплой rsync-ает рабочее дерево без учёта `.gitignore` (для `scripts/egress_probe/*.json|*.jsonl|*.out` в rsync стоит страховочный exclude, но полагаться на него не надо). Порядок и нормы: `scripts/egress_probe/README.md`. Запускает оператор.

- `$P/fetch_clients.sh` скачивает xray и hysteria версий из дефолтов ролей в `~/.cache/vpn-egress-probe`.
- `$P/admin_api.py METHOD /api/... [JSON]` — клиент админ-API прода: токен `vault_admin_api_token` читает из vault и не печатает, статус в stderr, база `ADMIN_API_BASE` (по умолчанию https://grinwer.online). Пример: `$P/admin_api.py GET /api/nodes > nodes.json`.
- `$P/collect_creds.py --user user1.json --nodes nodes.json --sub 21 (--device <id> | --idle-cover | --all-idle) [--idle-days 3] [--exclude-device <id>] [--only-nodes a,b] [--only-protos vless-reality]` собирает креды; ноду определяет резолвом хоста URI.
- `$P/egress_probe.py creds.json > probe.jsonl` меряет tcp, udp (STUN), v6 и openai-trace сквозь каждый кред.
- `$P/show_probe.py --nodes nodes.json --exits exits.json probe.jsonl [probe2.jsonl ...]` сводит матрицу, подписывает IP именами exit-ов и нод; в каждой строке `#<id>` креда (для SQL-сверки is_active), у ERR хвост текста (`ERR …unexpected eof while reading`).
- `$P/service_view_probe.py reality_view.json` показывает страну глазами YouTube (GL), Gemini API, OpenAI API: `ok (400)` / `ok (401)` норма, `🔴 BLOCKED` провал, `?` разобрать тело.
- `hy2_check.sh` на ноде: service, listen, bindDevice, ACL (только правила секции `acl:`, без комментариев шаблона), tls (`-- tls`: cert фронта, без `acme:`), wg-интерфейсы, DNAT-хоп, логи hysteria. Нормы (relay против direct) в README. Запуск: `cd infra/ansible && ansible all -i "<ip1>,<ip2>," -u root --ssh-common-args="-i ~/.ssh/vpn_provisioning_ed25519" -m script -a ../../scripts/egress_probe/hy2_check.sh > ~/.cache/vpn-egress-probe/out/hy2_check.out 2>&1 < /dev/null`.

Остальное:

- `scripts/check_whitelist_ip.py <ip>` — IP по публичному белому списку мобильного интернета, только информационно.
- `scripts/wl_beacon.sh links|collect <метка>` — живой тест белого списка с мобильной SIM, только для трёх зашитых адресов (nl-web, ufo-tr-01, vsin-ru-01).
- `scripts/audit_split_routing.sh --node <имя>` — статический split на reality и xhttp, только статик-ноды; «в норме» печатается всегда.
- `scripts/diag_node.sh` — текстовый отчёт на ноде (SERVICES, LISTENING PORTS, GEOIP…), на ноды не раскатан: `cd infra/ansible && ansible all -i "<ip>," -u root --ssh-common-args="-i ~/.ssh/vpn_provisioning_ed25519" -m script -a ../../scripts/diag_node.sh > ~/.cache/vpn-egress-probe/out/diag_node.out 2>&1 < /dev/null`.
- `scripts/diag_sub.sh <токен устройства>` — разбор выдачи сабы; дефолтный `ORIGIN_IP=45.14.244.140` устарел, задавать `ORIGIN_IP=194.76.146.166`.

Пока длинные однострочники отдавать тем же `-m script` из файла: при вставке ломаются кавычки и длинные строки (memory: feedback_ready_to_run_commands, reference_prod_introspection).
