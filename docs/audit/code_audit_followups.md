## 0. КРИТИЧНО, обнаружено при верификации фиксов: тест-сьют на dev красный

При настройке прогонного стенда выяснилось: на ветке `dev` (и на всех волнах фиксов) **60 из ~390 backend-тестов падают пре-экзистентно** — не из-за наших правок (падают идентично на чистом `dev`, в изоляции). Это ~15% сьюта. Значит CI либо не форсится на merge, либо его красный статус игнорируется — регрессии не отлавливаются.

Подтверждённые корневые причины (частичный список):
- `AttributeError: 'User' object has no attribute 'subscriptions'` — модель `User` (`backend/app/models.py`) не объявляет relationship `subscriptions`, но `balance.days_remaining` (`services/balance.py:653`) и ряд balance/renewal-тестов его используют. Один ORM-фикс (`subscriptions = relationship("Subscription", back_populates="user")`, без миграции) закрывает большой кластер.
- `test_vdsina_driver.py::test_order_server_injects_explicit_ssh_key` — тест устарел относительно драйвера (ждёт `host='ru-x'`, а драйвер намеренно шлёт `host=FQDN + ip4=1`, см. память проекта).

Полная кластеризация 60 падений — в работе (см. раздел «Repair pre-existing suite» ниже; будет дополнено). **Рекомендация P0: починить сьют до зелёного и сделать CI-гейт обязательным**, иначе автоматические фиксы невозможно защитить от регрессий.

## 6. Сетевой аудит — отложенное (needs_decision / needs_migration)

Дополняет `network_audit_report.md`. Из 62 находок сетевого аудита 52 исправлено в волне сетевых фиксов; ниже — отложенное (требует кросс-файловых/серверных изменений, миграций или UI-одобрения). Частичные фиксы «своей части» уже применены, здесь — что осталось.

### ✅ Закрыто после волны (2026-07-10)
- **ssh_skipped в reachability-тике (хвост #97, был Critical и ВЫПАЛ из этого трекера)**: флаг `PathProbeResult.ssh_skipped` волна добавила, но `run_node_reachability_tick` продолжал решать только по `ssh_ok` — отсутствие paramiko/ssh-ключа на контроллере клало весь флот в ложный DOWN со штормом пушей. Закрыто: skip-проба недиагностична (статус/серию/`last_probe_at` не трогаем) + один агрегированный алерт `reachability_ssh_skipped` с дедупом («мониторинг слеп», down-детект и recovery заморожены).

### Требуют миграции БД
- **Флап-детектор нод** (`worker.py` / `health.py`): «мигающая» нода (ok↔down) никогда не алертит, т.к. любой ok-проб сбрасывает серию. Нужен персистентный cross-tick счётчик — колонки `flap_count INTEGER DEFAULT 0` + `last_flip_at` на `VPNNode` И `WGExitNode` (в памяти считать нельзя — каждый тик свежая сессия). Логика: инкремент на каждом переходе с экспоненциальным затуханием, алерт при превышении порога за окно.

### Требуют серверной сверки (протоколы — трогать осторожно)
- **Hysteria2 client-URI без username** (`provisioning.py`): сервер аутентифицирует по userpass-мапе `username→password`, а URI отдаёт только пароль (`hy2://pass@`). Фикс меняет реальную auth-строку (`hy2://user:pass@`) — нужно: прокинуть username в `_build_hysteria2_credential` (3 call-site), URL-энкодинг, переписать `_extract_hy2_password`. Требует проверки серверной стороны (config.yaml.j2 install_hysteria2), иначе сломает подключение.
- **Hysteria2 sni=IP → ACME провал** (`provisioning.py` + `install_hysteria2` роль + `api/nodes.py`): при пустом sni и домене-IP ACME гарантированно не выпустит сертификат. Свою часть (громкий warning) добавил; настоящий фикс — self-signed при IP-домене в роли + валидация sni как FQDN в api/nodes.py.
- **Hysteria2 (UDP) не в health-check** (роль `check_node_health`): `health_ports` (TCP wait_for) намеренно не покрывает UDP. Нужна UDP-liveness проверка в ansible-роли (`systemctl is-active hysteria-server` + `ss -ulnp`) с прокидкой в статус ноды.

### Требуют кросс-файловых изменений
- **Operator-routing при фейловере** (`client_control.py` + `provisioning.py`): `choose_node`/`migrate_subscription_to_free_node` не учитывают operator-routing матрицу — юзера на заблокированном операторе гоняет по таким же битым нодам. Нужен опциональный параметр `operator` в `choose_node` с exclude/penalize по confident-fail ячейкам (L-сложность).
- **Персистентность 15-мин follow-up** (`health.py` + `api_extensions.py` + `admin_notify.py` + `bot/bot.py` + `bot/handlers.py`): follow-up «всё ещё не работает?» живёт в памяти бота, теряется при рестарте. Нужно: backend кладёт `still_broken_prompt` в `/api/notifications/pending` по истечении окна; бот обрабатывает новый тип в notification_poller.

### Требуют UI-одобрения (frontend — не менял вёрстку)
