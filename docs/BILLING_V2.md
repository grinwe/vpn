# Billing V2 — ежемесячное списание

## Контекст

Billing V1 (daily tick) оказался запутанным для юзеров: «хватит на 598 дней» пугает,
`prepaid_kopecks` + ежедневный charge tick создают лишнюю сложность.
Переходим на простую ежемесячную модель.

## Модель

### Баланс и топап

- `User.balance_kopecks` — единый кошелёк, пополняется через Stars / ручную оплату.
- **Минимальный топап** = цена самого дешёвого видимого плана (динамически из БД).
- Вывод средств невозможен — gym-модель: деньги внесены, остаются на счёте навсегда.

### Активация подписки

1. `balance -= plan.price` (разово, за весь период).
2. `paid_until = now + plan.duration_days`.
3. `auto_renew = True` (по умолчанию).
4. Провижинг девайса как раньше.

### Автопродление (воркер, раз в час)

1. Находим подписки с `paid_until <= now AND auto_renew = True AND status = active`.
2. Если `balance >= plan.price` → списываем, `paid_until += plan.duration_days`.
3. Если баланс недостаточен → `status = expired`, девайсы отзываются, уведомление юзеру.

Подписки с `auto_renew = False` НЕ продлеваются:
когда `paid_until` истёк → `status = expired`.

### Отключение автопродления («Отписаться»)

- `auto_renew = False`.
- Доступ **сохраняется** до `paid_until`.
- В карточке: «Активна до 10 мая. Автопродление отключено.»
- Юзер может включить обратно в любой момент до истечения.

### Смена тарифа (proration)

Пример: юзер на Pro (500 ₽/мес), прошло 12 дней из 30.

1. Остаток текущего: `500 × (30 - 12) / 30 = 300 ₽` → возврат на баланс.
   Возврат капится ценой старого плана (`min(refund, old_price)`): заморозка
   растягивает `expires_at` на `FREEZE_DAYS`, и без капа остаток мог бы
   превысить `duration_days` → рефанд > 100 % цены.
2. Новый план: `balance -= new_plan.price`, `paid_until = now + new_plan.duration_days`.
3. Девайсы: если план сменился на тот же тип ноды — ничего не трогаем.
   Если нода другая — revoke старых, provision новых.

Endpoint: `POST /api/webapp/subscriptions/{id}/change_plan` с `{ plan_id }`.

### Заморозка

| Параметр | Значение |
|---|---|
| Количество в год | 1 раз |
| Длительность | 7 дней |
| Досрочная разморозка | Да, но повторная заморозка заблокирована до конца года |
| Эффект на `paid_until` | `paid_until += 7 дней` (юзер не теряет оплаченные дни) |
| Девайсы | Отзываются на время заморозки |

При нажатии «Разморозить»: предупреждение
«Если разморозите сейчас — заморозить повторно не получится до конца года».

Кнопка заморозки **скрыта**, если `auto_renew = False` (нет смысла замораживать подписку, которая не продлится).

## UX после оплаты / активации

### Проблема

Юзер оплатил, его перекинуло на главную страницу — и непонятно что делать.
Начинает бегать глазами, искать что скопировать. Нужно сразу показать конфиг.

### Решение: экран «Подписка готова»

После активации вместо попапа «Хватит на N дн.» — отдельный экран/секция:

```
✅ Тариф «Pro» активирован
   Следующее продление через 30 дней

┌─────────────────────────────┐
│         [QR-код]            │
│                             │
│  vless://a0da04...@host:443 │
│  [  Скопировать конфиг  ]   │
└─────────────────────────────┘

Откройте Hiddify / v2rayNG → отсканируйте QR
или скопируйте ссылку и импортируйте вручную.
```

Ключевые принципы:
- **QR сразу открыт** — не по кнопке, а виден на экране. Юзер с другого
  телефона / ноута сразу сканирует.
- **Конфиг-ссылка** видна частично (первые ~30 символов + ellipsis),
  рядом кнопка «Скопировать».
- **Подсказка** под QR: куда импортировать (Hiddify / v2rayNG).
- Кнопка «На главную» внизу.

### Главная страница (Home)

На карточке подписки конфиг тоже должен быть легко доступен:
- QR **свёрнут** по умолчанию (в отличие от экрана активации).
- Строка конфига с обрезкой + кнопка копирования — **всегда видна**.
- Тап по строке или по «QR» — раскрывает QR-код.

```
Pro                              активна
500 ₽/мес · до 10 мая

vless://a0da04...@host:443   [📋]
[▶ Показать QR]

[toggle] Автопродление: вкл
[Заморозить на 7 дн.]  [Сменить тариф]
```

## Что убираем

- `prepaid_kopecks` — больше не нужен (колонка остаётся, обнулена миграцией).
- `next_charge_at` — заменяется на `expires_at` (который уже существовал).
- Daily charge tick в воркере — заменён на monthly renewal check.
- `EXTRA_DEVICE_DAILY_KOPECKS` — доп. устройства входят в план, без доплат.
- `_daily_cost_kopecks()`, `sub_days_remaining()`, `days_remaining()` — legacy stubs.

## Что добавляем / меняем

### БД

- `Subscription.expires_at` — переиспользуется как `paid_until` (уже существовал).
- `Subscription.auto_renew: bool` — уже существовал, теперь используется в UI.
- `Subscription.has_frozen_this_year: bool` — новое поле (миграция 0015).

### Бэкенд

- `services/balance.py` — рефакторинг: убираем daily tick, добавляем `renew_subscription()`,
  `change_plan()`, упрощаем `freeze/unfreeze` (сдвиг `paid_until`).
- `worker.py` — `run_balance_charge_tick()` → `run_renewal_tick()`:
  check `paid_until <= now`, renew or expire.
- `api_webapp.py` — endpoints: toggle auto_renew, change_plan. Обновить activate, freeze, unfreeze.
- `schemas.py` / `api.ts` — `paid_until`, `auto_renew` в SubscriptionExtra.

### Фронт (webapp)

- Карточка подписки: toggle автопродления, «до N мая», кнопка «Сменить тариф».
- Попап активации: «Следующее продление через 30 дней».
- Убрать «₽/день», `days_remaining` — не актуально.

### Бот

- `/balance` — показывать `paid_until`, статус автопродления.

## Миграция данных

Существующие подписки с `next_charge_at`:
- `paid_until = next_charge_at + remaining_prepaid_days` (вычисляем из prepaid_kopecks / daily_rate).
- Если `prepaid_kopecks = 0` — `paid_until = next_charge_at`.
- `auto_renew = True` для всех активных.

Alembic миграция: добавить `paid_until`, заполнить из расчёта, потом воркер начнёт
работать по новой модели.
