Проведи технический аудит моей собственной кодовой базы.

Цель аудита — найти проблемы качества, надежности, поддержки и архитектуры приложения.

Сначала не выполняй аудит, а предложи план работы и формат итогового отчета.

Проверь следующие направления:

1. Потенциальные ошибки в коде:

* падения приложения;
* необработанные исключения;
* некорректная работа с состоянием;
* проблемы асинхронности;
* гонки данных;
* ошибки таймаутов;
* некорректная обработка edge-case сценариев;
* проблемы валидации входных данных.

2. Архитектура:

* сильная связанность компонентов;
* дублирование логики;
* сложность расширения;
* сложность тестирования;
* неочевидные зависимости;
* проблемные границы между модулями;
* потенциальные узкие места производительности.

3. Надежность:

* поведение при ошибках;
* восстановление после сбоев;
* корректность fallback-сценариев;
* логирование;
* диагностика;
* обработка невалидных конфигураций;
* устойчивость к частичной недоступности зависимостей.

4. Поддерживаемость:

* читаемость кода;
* структура проекта;
* качество абстракций;
* тестируемость;
* места, которые сложно менять без риска сломать приложение.

Для каждой найденной проблемы укажи:

* название;
* где находится проблема;
* описание простым языком;
* критичность: Critical / High / Medium / Low;
* почему это важно;
* как исправить;
* пошаговый план исправления;
* примерную сложность;
* приоритет внедрения.

Не придумывай данные, которых нет в коде. Если вывод является предположением — явно помечай его как предположение.


Проведи аудит сетевой логики моего приложения с точки зрения надежности, корректности и пользовательского опыта.

Фокус только на стабильности и качестве работы приложения. Не нужны эксплуатационные сценарии, обход защитных механизмов или инструкции для злоупотребления сетевой инфраструктурой.

Проверь:

* обработку сетевых ошибок;
* таймауты;
* повторные попытки;
* fallback-сценарии;
* поведение при смене сети;
* поведение при потере соединения;
* корректность применения пользовательских настроек;
* обработку частично невалидной конфигурации;
* диагностику проблем соединения;
* логирование;
* UX-сообщения об ошибках;
* потенциальные причины деградации производительности.

Для каждой проблемы укажи:

* название;
* место в коде или компоненте;
* описание простым языком;
* критичность;
* влияние на пользователя;
* способ исправления;
* пошаговый план исправления;
* сложность;
* приоритет.



Подготовь roadmap MVP мобильного приложения для Apple-платформы.

Цель — сделать удобный клиент с качественным UX, надежной сетевой логикой, диагностикой состояния подключения и автоматическим выбором оптимальной конфигурации на основе доступности и качества соединения.

Сначала предложи план работы и структуру результата.

Нужно описать:

1. Архитектуру MVP:

* UI-слой;
* core-логику;
* сетевой слой;
* слой конфигурации;
* диагностику;
* логирование;
* обновление настроек;
* обработку ошибок.

2. Основные функции MVP:

* подключение к инфраструктуре сервиса;
* получение пользовательской конфигурации;
* проверка доступности;
* автоматический выбор оптимального варианта подключения;
* базовый fallback;
* диагностика проблем;
* понятные статусы для пользователя;
* простой onboarding.

3. Ограничения iOS:

* какие системные ограничения нужно учитывать;
* какие разрешения могут потребоваться;
* какие функции лучше отложить;
* какие решения подходят для MVP.

4. Roadmap:

* исследование;
* архитектура;
* MVP;
* диагностика;
* надежность;
* UX/UI;
* тестирование;
* подготовка к релизу.

5. Дизайн:

* Apple-like визуальный стиль;
* минималистичный интерфейс;
* понятная визуальная иерархия;
* аккуратные отступы;
* минимум ручных действий;
* понятные статусы и ошибки.

Результат должен быть практичным, простым языком, без лишней воды.
