# Probe agent

Внешний проверяльщик доступности VPN-нод. Запускается **вне** основного
сервиса — по одному экземпляру на «точку наблюдения» (RU-MTS, RU-Билайн,
KZ, EU, …). Каждый экземпляр раз в `PROBE_INTERVAL` секунд:

1. Тянет список целей: `GET /api/probes/targets`.
2. Для каждой пары `(host, port)` делает проверку:
   - `tcp` — просто TCP-коннект за `PROBE_TIMEOUT` секунд;
   - `tls` — TCP + TLS handshake c нужным SNI (валидацию цепочки не
     делаем — ShadowTLS специально «одалживает» чужой SNI).
3. Отправляет результат обратно: `POST /api/nodes/{id}/probes`.

Агент stateless: всё состояние живёт в backend'е. Можно перезапускать,
переносить между регионами, держать десяток копий — важно только, чтобы
`SOURCE_REGION` был уникальным и совпадал с меткой, по которой бэкенд
будет агрегировать «где эту ноду блочат».

## Запуск

```bash
docker build -t vpn-probe probes/

docker run --rm --name probe-ru-mts \
  -e BACKEND_URL=https://vpn.example.com \
  -e BACKEND_TOKEN=... \
  -e SOURCE_REGION=ru-mts \
  -e SOURCE_KIND=residential \
  -e PROBE_INTERVAL=60 \
  vpn-probe
```

## Переменные окружения

| Имя | Обязательна | Дефолт | Описание |
|---|---|---|---|
| `BACKEND_URL` | да | — | База API, без `/api` |
| `BACKEND_TOKEN` | да | — | Тот же admin-токен, что у бэкенда |
| `SOURCE_REGION` | да | — | Метка точки наблюдения, напр. `ru-mts` |
| `SOURCE_KIND` | нет | — | Свободная метка: `residential`, `datacenter`… |
| `PROBE_INTERVAL` | нет | `60` | Секунд между полными sweep'ами |
| `PROBE_TIMEOUT` | нет | `5` | Таймаут одной проверки, сек |
| `PROBE_CONCURRENCY` | нет | `16` | Параллелизм в рамках одного sweep'а |
| `HTTP_TIMEOUT` | нет | `10` | Таймаут на HTTP до бэкенда, сек |
| `LOG_LEVEL` | нет | `INFO` | Уровень логирования |

## Где разворачивать

- **RU**: дешёвая VPS у рос. провайдера (МТС Cloud, Selectel в RU-зоне) —
  видит блокировки TSPU так же, как обычный клиент.
- **KZ / BY**: симметрично, для соседних юрисдикций с похожим профилем
  блокировок.
- **EU**: «эталонная» точка — если ноду не видно даже оттуда, она реально
  лежит, а не «заблокирована».

Backend агрегирует результаты по `source_region` и автоматически
мигрирует подписки со сломанных нод — см. `services/health.py`.

## Что НЕ делает агент

- Не проверяет работоспособность VPN-туннеля целиком (для этого нужен
  реальный клиент). Мы намеренно ограничиваемся L4/L5: блокировка почти
  всегда проявляется именно там, а полноценный клиент-эмулятор — это
  уже совсем другой сервис.
- Не хранит историю локально. Все наблюдения — в Postgres на бэкенде.
- Не нуждается в SSH-ключах от нод и вообще ни в каких секретах VPN.
  Только admin-токен API.
